Each row is a Kalshi market matched to the Polymarket market judged most likely to be the same market (raise "min similarity" for stricter matches, lower it to see more candidates). YES gap and NO gap are computed independently: YES gap is Kalshi's YES price minus Polymarket's YES price; NO gap is Kalshi's NO price (1 − YES, since Kalshi has no separate NO market) minus Polymarket's own NO price (a separately traded outcome on Polymarket, not just 1 − YES). A positive gap means Kalshi is priced higher on that side. Matching is a lightweight text-similarity heuristic (see arb/matching/discover.py), not verified resolution-criteria matching -- click through and read both markets before treating any row as a real pair. This page shows data only; it does not compute fees, size trades, or place orders.
Each scan runs several real LLM calls per candidate (rule extraction, world-state proposal, hole detection) -- this is deliberately slower than the Discovery tab's refresh and bounded to "max candidates" pairs, not the whole market. Only TRUE ARBITRAGE is shown by default; use "show" to reveal weaker classifications. Click a row to see the full payoff matrix and recommended trade.
Click "Scan for opportunities" to run the verification engine against the top matched pairs.
Every number here comes from a live re-fetch of both order books, a fresh LLM-proposed set of resolution states (plus an adversarial hole-detector pass), and a linear-programming stake optimizer -- nothing is cached from a previous scan. "Worst-Case P&L" is the guaranteed profit across every identified resolution state; if it's negative by even a cent, the pair is never labeled TRUE ARBITRAGE. See arb/arbitrage/ for the full engine.
